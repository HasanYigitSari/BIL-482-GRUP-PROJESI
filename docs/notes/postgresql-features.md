# PostgreSQL Features

1. **Tables and relationships** — Organize records into tables and connect them using primary and foreign keys.
2. **Constraints** — Enforce data rules with `UNIQUE`, `NOT NULL`, `CHECK`, primary keys, and foreign keys.
3. **Rich data types** — Store text, numbers, exact decimals, booleans, UUIDs, timestamps, arrays, and more.
4. **JSON / JSONB** — Store and query flexible structured data alongside regular columns.
5. **Indexes** — Speed up lookups and filtering, with additional storage and write overhead.
6. **Full-text search** — Search text and rank matching results within PostgreSQL.
7. **Views** — Save a query as a virtual table to simplify access or expose selected data.
8. **Materialized views** — Store a query’s results for faster reading; refresh them when needed.
9. **Transactions** — Group multiple changes into an all-or-nothing operation.
10. **Multiversion concurrency control (MVCC)** — Use data snapshots to support concurrent reads and writes.
11. **Transaction isolation and locks** — Control how simultaneous operations interact and coordinate conflicting changes.
12. **Database functions** — Define reusable logic that runs inside PostgreSQL.
13. **Triggers** — Automatically run a database function when an insert, update, delete, or other supported operation occurs, optionally checking a condition.
14. **`LISTEN` / `NOTIFY`** — Send event notifications to connected listeners; durable job storage requires an additional design.
15. **Database roles** — Define database identities and groups to which permissions can be assigned.
16. **Privileges: `GRANT` / `REVOKE`** — Control which roles can read, insert, update, delete, execute functions, or perform other operations.
17. **Column-level permissions** — Restrict access to particular fields within a table.
18. **Row-level security (RLS)** — Define policies controlling which individual records a role can read or modify.
19. **Field encryption** — Encrypt selected values using application code or the `pgcrypto` extension; decryption requires a key.
20. **Connection encryption (TLS)** — Encrypt traffic between the application and database.
21. **Encryption at rest** — Protect stored database files through disk, filesystem, or hosting-provider encryption.
22. **Password hashing** — Store salted password hashes, typically generated by an application-side Argon2id library, for password verification.
23. **Schema migrations** — Record and apply changes to database structure using tools such as Prisma.
24. **Migration history in Git** — Version migration files alongside application code so database changes can be reviewed and reproduced.
25. **Audit logs and record history** — Preserve who changed what and when through an explicitly designed audit/history system, potentially using triggers.
26. **Backups and restoration** — Save database copies and restore them when necessary.
27. **Point-in-time recovery (PITR)** — Recover to a chosen earlier point using suitable backups and archived transaction logs.
28. **Replication and standby servers** — Maintain additional database copies for availability, failover, or read workloads.
29. **Extensions** — Add capabilities beyond the core database, such as the cryptographic functions provided by `pgcrypto`.
